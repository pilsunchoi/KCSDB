# API 명세 분석: 관세청_품목별 국가별 수출입실적(GW)

본 문서는 공공데이터포털 Swagger UI에서 추출한 API 명세를 분석하고, 본격 호출 전 직접 검증해야 할 항목을 정리합니다.

## 학생용 핵심 교훈

> **"API 명세서는 출발점이지 도착점이 아니다."**
>
> 명세서에는 종종 누락·모호한 부분이 있습니다. 본격 수집 코드를 짜기 전에:
> 1. 명세에서 *명시된 것*과 *불명확한 것*을 구분
> 2. 불명확한 부분을 답할 *시범 호출*을 설계
> 3. 시범 결과로 명세를 보완한 뒤 본격 수집

---

## 1. 확정 정보

### Endpoint

```
http://apis.data.go.kr/1220000/nitemtrade/getNitemtradeList
```

- 도메인: `apis.data.go.kr` (공공데이터포털 표준)
- 기관코드: `1220000` (관세청)
- 서비스명: `nitemtrade`
- 액션: `getNitemtradeList`

### 응답 형식
- XML (JSON 옵션 미언급)

### 요청 파라미터

| 영문명 | 자릿수 | 필수 | 샘플 | 의미 |
|---|---|---|---|---|
| `serviceKey` | 100 | ✓ | (인증키) | 공공데이터포털 발급 키 |
| `strtYymm` | 6 | ✓ | `201601` | 시작년월 (YYYYMM) |
| `endYymm` | 6 | ✓ | `201601` | 종료년월 (YYYYMM) |
| `hsSgn` | 10 | ○ | `1001999090` | HS 코드 |
| `cntyCd` | 2 | ○ | `US` | 국가코드 |

### 응답 필드

| 영문명 | 한국어 | 자릿수 | 비고 |
|---|---|---|---|
| `resultCode` | 결과코드 | 2 | `00` = 성공 |
| `resultMsg` | 결과메시지 | 50 | `OK` 등 |
| `year` | 기간 | 7 | `2016.01` 형식 (소수점 표기 주의) |
| `statCdCntnKor1` | 국가명 | 30 | 한국어 |
| `statCd` | 국가코드 | 5 | 응답은 5자리 (입력 2자리와 다름) |
| `statKor` | 품명 | 60 | 한국어 |
| `hsCd` | HS코드 | 10 | 가변 자릿수 추정 |
| `expWgt` | 수출중량 | 15 | kg (순중량) |
| `expDlr` | 수출금액 | 17 | USD (확인 필요) |
| `impWgt` | 수입중량 | 15 | kg |
| `impDlr` | 수입금액 | 17 | USD |
| `balPayments` | 무역수지 | 15 | USD |

### 갱신 정보
- **주기**: 매월 15일경 전월까지의 자료 현행화
- **잠정 vs 확정**: 명세에 별도 표기 없음 (검증 필요)
- **금액 기준**: 수출 FOB / 수입 CIF, USD

### 한도
- 개발계정: 일일 10,000건
- 운영계정: 활용사례 등록 시 증액 가능

## 2. 결정적 제약

### 제약 A: 조회기간 1년 이내

`strtYymm`과 `endYymm`의 차이가 12개월을 넘을 수 없습니다.

**영향**: 2010–2026 수집 시 **연도별 분할 호출 필수**.

```
2010년: strtYymm=201001, endYymm=201012  → 호출 1
2011년: strtYymm=201101, endYymm=201112  → 호출 2
...
2026년: strtYymm=202601, endYymm=202612  → 호출 17
```

다른 차원(국가, HS) 추가 분할 시 호출 수는 곱연산으로 증가.

### 제약 B: 일일 10,000건

호출 예산 관리 필수. 본격 수집 전 한 호출에 어느 정도 데이터가 오는지 확인 후 전략 수립.

### 제약 C: XML 응답

JSON이 아닌 XML 파싱 필요. `lxml` 또는 표준 `xml.etree`로 처리.

## 3. 명세에서 불명확한 사항 (시범 호출에서 확인)

### Q1. 페이지네이션 파라미터 존재 여부

**관찰**: 화면에 보이는 요청 파라미터가 5개뿐. data.go.kr 다른 API들은 보통 `pageNo`, `numOfRows`를 가짐.

**가설**:
- (a) 명세서에 누락되었으나 실제로는 동작 (다른 API와 동일)
- (b) 이 API는 페이지네이션 없이 한 번에 모든 결과 반환

**확인 방법**: 시범 호출에서 `pageNo=1&numOfRows=10` 추가하여 응답 차이 관찰.

### Q2. hsSgn 생략 시 응답 HS 자릿수

**관찰**: 옵션 파라미터 `hsSgn`을 생략하면 무엇이 반환되는가?

**가설**:
- (a) 모든 HS10 코드 (가장 풍부, 가장 큰 응답)
- (b) HS6 또는 HS4 자동 집계
- (c) 별도 디폴트 동작

**확인 방법**: 한 달치 데이터를 `hsSgn` 없이 조회하여 응답의 `hsCd` 값 분포 확인.

### Q3. cntyCd 생략 시 전체 국가 반환 여부

**확인 방법**: 한 달치 단일 HS 코드 데이터를 `cntyCd` 없이 조회.

### Q4. 국가코드 체계

**관찰**: 입력은 2자리(`US`), 응답 `statCd`는 최대 5자리.

**가설**: 관세청 자체 코드일 가능성. ISO 알파-2와 일치 여부 검증 필요.

**확인 방법**: 한 달치 데이터에서 `statCd` 값들을 ISO 알파-2 표준과 비교.

특히 다음 케이스 주목:
- 영국: GB vs UK
- 대만: TW vs TA
- 홍콩/마카오 분리 여부
- 미국령 (PR, GU) 분리 여부

### Q5. 금액 단위

**관찰**: 명세에 "USD"라고만 표기, 단위(원본 USD vs 천USD)는 명시 없음.

**확인 방법**: 알려진 무역 통계와 대조. 예: 2024년 1월 對미국 수출 약 100억 USD 수준이어야 함.

### Q6. HTTPS 지원

명세는 `http://`로 표기. HTTPS도 가능한지 확인.

### Q7. year 필드 형식

샘플 `2016.01` — 소수점 표기. 파싱 시 `int(year)`로 변환하면 2016이 되어 월 정보 손실. 문자열로 처리 필수.

### Q8. 한 호출당 최대 응답 행수

페이지네이션이 동작한다면 numOfRows 최대값. 동작 안 하면 응답이 어디서 잘리는지(또는 안 잘리는지).

## 4. 시범 호출 설계

위 Q1–Q8을 답하기 위한 단계적 호출 설계:

### Step 1: 최소 호출 (응답 구조 확인)
```
strtYymm=202401, endYymm=202401, hsSgn=1001999090, cntyCd=US
```
→ 응답 1건 또는 0건. XML 구조와 필드 확인.

### Step 2: 페이지네이션 시험
Step 1과 동일하지만 `pageNo=1&numOfRows=10` 추가.
→ 차이 비교.

### Step 3: 옵션 파라미터 생략
```
strtYymm=202401, endYymm=202401, cntyCd=US
```
→ hsSgn 없을 때 동작.

### Step 4: 더 큰 응답
```
strtYymm=202401, endYymm=202401
```
→ 한 달치 전체. 응답 행수, 페이지네이션 필요성 확인.

### Step 5: 검증값 추출
응답에서 對미국 수출 합계를 산업통상자원부 발표치와 비교 → 단위 확정.

## 5. 본격 수집 전략 결정 매트릭스

시범 호출 결과에 따라 수집 전략이 달라집니다:

| 시나리오 | 수집 전략 | 예상 호출 수 |
|---|---|---|
| 페이지네이션 동작 + 1년 단위 OK | 연도별 호출 + 페이지 루프 | 17 × 평균 페이지수 |
| 페이지네이션 동작 + 1년이 너무 큼 | 월별 호출 + 페이지 루프 | 204 × 평균 페이지수 |
| 페이지네이션 미동작 + 한 번에 다 옴 | 연도별 단일 호출 | 17 |
| 페이지네이션 미동작 + 잘림 | 국가별 또는 HS별 분할 | 다양 |

본격 수집 전 이 매트릭스 중 어느 시나리오인지 확정합니다.
